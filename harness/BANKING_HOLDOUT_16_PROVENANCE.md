# `banking_holdout_16/` — provenance

Generated by `harness/identify_holdout_16.py` (non-frozen, read-only) on 2026-08-12.

These sixteen APKs are the negative class of SetuGuard's headline PS1 result — AUC(malicious vs `banking_holdout_16`) = **0.4113**. Until this file existed the repository recorded nothing about what they are, so the question *"which sixteen banks?"* had no answer.

---

## FINDING — there are no banks in `banking_holdout_16/`

**All sixteen are malware samples.** Not one is a legitimate banking app. The directory is a sixteen-sample partition of the CICMalDroid **Banking malware** archive — the same archive `cicmaldroid_banking/` was extracted from.

### Evidence 1 — the arithmetic is exact

```
$ tar -tzf Banking.tar.gz | grep -c '\.apk$'      ->  2505
$ ls -1 cicmaldroid_banking/*.apk    | wc -l        ->  2489
$ ls -1 banking_holdout_16/*.apk     | wc -l        ->    16
                                                        -----
                                          2489 + 16  =  2505
```
Set-differenced both ways: **zero** tarball entries outside the two directories, **zero** files in either directory absent from the tarball, **zero** overlap between the two directories. `banking_holdout_16/` is the complement of `cicmaldroid_banking/` within `Banking.tar.gz`. All sixteen filenames were confirmed present in the tarball listing individually.

### Evidence 2 — no certificate belongs to a bank, or to any real publisher

Every one of the sixteen is **self-signed**. The subjects are:

- Keyboard mash: `sdsdfsdf`, `sasasa`, `zxzxzx`, `32131312312321312`, `7`
- The AOSP **public test key** — `android@android.com / Android / Mountain View / California / US` — on three samples. No app distributed through Google Play can carry this key; it is the publicly-known platform test certificate.
- `android-debug` — the Android Studio debug key — on two samples.
- `DarkNess / Space / Galaxy / GA` on three samples.
- `Sergio Mavrodi` — the name of a Russian Ponzi-scheme operator — on one.

### Evidence 3 — the package names and labels are not banking apps

`com.example.myapp` is the Android Studio template default, which Google Play rejects outright. `zzzzzz.xxxxxx.cccccc` and `qrprjp.scxrxw.upuwjg` are randomised namespaces, a repackaging-kit signature. `com.google.game.store` and `com.sms.google` masquerade as Google. `com.trdos.cores` appears **twice**, as two different files carrying two different labels (*Worms 2: Armageddon* and *Семейная ферма*) — one package, two repackaged payloads.

Labels include *Free PornTube*, *Yatzy Heaven - Bikini Beach*, *MMS-Центр*, *获奖证书* ("award certificate"), and Korean parcel-delivery lures (*스마트 택배*, *CJ대한통운 택배*) — the standard smishing bait set. Exactly one sample carries a banking label, **신한S뱅크** (Shinhan S Bank), and it is a *fake*: package `com.xinhannewbank` (the real app is `com.shinhan.sbanking`), signed with the AOSP test key. It is a banking trojan impersonating a bank, which is a positive, not a negative.

### What this does to the headline result

| Claim as written across the repo | What the evidence supports |
|---|---|
| AUC 0.4113 = "malware does not rank above legitimate banking apps" | **Void.** It is 360 malware vs 16 malware from the same archive — a within-class ranking artifact measuring nothing about legitimate apps. |
| "15/16 legitimate banking apps false-positive" | **Inverted.** 15/16 held-out *malware* samples correctly flagged — a 93.8% detection rate, currently written up as the project's central failure. |
| "1 app scored 0.28, below the 0.30 threshold" (a correct benign call) | **A miss.** One malware sample evaded the scorer. |
| "Banking apps outscore confirmed malware, 0.688 vs 0.614" | Both groups are malware. These sixteen simply score higher than the cicmaldroid sample average. |
| "Static analysis cannot separate banking malware from legitimate banking apps — the classes are convergent by construction" | **Unmeasured.** A plausible hypothesis with no supporting measurement in this repo. |

**AUC(malicious vs general F-Droid benign) = 0.9366 is unaffected** and remains the project's one genuine PS1 separation number. `fdroid_benign_apks/` is a real benign corpus, independently sourced from F-Droid.

A second consequence, easy to miss: `SESSION_LOG.md:219` records that term selection for scorer-v2 ranked discriminative power over "malicious sample vs **fdroid_benign + holdout16**". Those sixteen sat in the **negative** pool. They are malware. So the term ranking that justified the three scorer-v2 deletions ran with roughly 5% label noise in its negative class — a labelling error, not merely the holdout-contamination previously recorded.

### How the error happened

Semantic drift on the directory name, traceable in the repo. `SetuGuard_Development_Roadmap_v2.md:16` (2026-07-06) is the earliest occurrence: *"F-Droid + 16 real banking-app holdout"*. `harness/sample_set_banking_holdout_16.txt:2-3` hardcodes the reading as a comment: *"The 16 real banking APKs… Every non-benign verdict here is a false positive on real bank apps."* From there it propagated to `docs/evidence/2026-08-12_scorer_v2.md:121`, `SESSION_LOG.md:172,233,352`, `PS1_Defects_and_Improvements.md:67`, and `CONTEXT.md`. "Banking holdout" means *held out from the Banking [malware] set*; it was read as *a holdout of banking apps*.

The repo flagged this risk to itself and was not heard: `PS1_Defects_and_Improvements.md:144` (D9) states *"the F-Droid pull… and the 16 real banking APKs are **unsourced**. Until they exist, the FP number cannot be measured."* The FP number was measured anyway, five weeks later, against a corpus that was never sourced because it never existed.

## How tiers were assigned

From the **package name and the certificate subject only**. Not from the app label, not from a web search, not from the version string. The rule table lives in `harness/identify_holdout_16.py:TIER_RULES` and every entry is a naming fact — a first-party package namespace, or an institution named in the certificate's Organization field.

| Tier | Definition |
|---|---|
| **A** | Scheduled commercial bank first-party app |
| **B** | UPI / PSP app |
| **C** | NBFC, wallet, or fintech |
| **Unknown** | Package name and certificate do not settle it |

**Unknown is marked freely and is not a shortfall.** This scheme is reused as the *pre-registered* inclusion rule for the planned AndroZoo corpus build, where the Tier-A gate is the whole experiment. A confident wrong tier there costs more than an honest Unknown, so the classifier abstains rather than guesses.

**All sixteen came back Unknown, and that is the correct answer.** The tier scheme is a *bank-identification* rule; none of these is a bank app, so none matches. The scheme abstaining on sixteen malware samples is the scheme working. Its value is now forward-looking: it is the pre-registered rule for building the real Tier-A holdout that this project has never had.
